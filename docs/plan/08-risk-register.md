## 2. Top 5 深挖

### 2.1 R-01：编译验证缺失（最紧急，必须在 M0 前解决）

**现状**：本机 `api.nuget.org` 不可达（`NU1301`），本地缓存只缺一半包（有 `Newtonsoft.Json 13.0.3`、`Mono.Cecil 0.11.6`、`Microsoft.Win32.Registry 5.0.0`；缺 `Autofac`、`SharpZipLib`、`TxFileManager`、`NJsonSchema`、`YamlDotNet`、`ValveKeyValue` 等）。

**按顺序尝试**：

| 步 | 动作 | 成功判据 |
|---|---|---|
| 1 | 检查网络：`curl -I https://api.nuget.org/v3/index.json`，确认是 DNS/代理/证书哪一层 | 能拿到 200 |
| 2 | 若被墙/公司网络：配置镜像源（如 Azure DevOps 公共源、本地缓存的离线 feed、`nuget.config` 加 `packageSourceMapping`） | `dotnet restore` 成功 |
| 3 | 若证书问题：`NUGET_CERT_REVOCATION_MODE=offline` 或导入企业根证书 | restore 成功 |
| 4 | 离线兜底：从另一台可联网机器 `dotnet restore --packages ./offline` 后整体拷贝缓存目录 | 本地缓存齐全 |
| 5 | 仍失败：**降级为"静态分析 + 只编译 Core 的子集"**（Core 若无 UI 依赖可先单独编译看是否缺包），并把新 UI 骨架推迟到有网环境 | 至少能 `dotnet build Core/CKAN-core.csproj` |

**这是全项目第一个必须先解决的事**，因为后面所有工时估算都假设"能编译"。

### 2.2 R-02：Core 的同步交互回调

**机理**：`InstallList` 在安装线程上调用 `User.RaiseYesNoDialog(...)` 并**等待返回值**（同步）。若调用链恰好从 UI 线程发起且 UI 线程同步等待安装结果，就会：

```
UI 线程 --同步等待--> 安装线程 --同步等待--> UI 线程（死）
```

**缓解三重保险**：

1. 发起安装的命令体是 `async`，`await Task.Run(...)`，UI 线程全程空闲；
2. `AvaloniaUser.RaiseYesNoDialog` 用 `Invoke`（不是 `Post`），并且**在入口断言自己不在 UI 线程**（`if (_ui.CheckAccess()) log.Warn(...)` —— 真在 UI 线程时说明调用链错了）；
3. 提供 `ConfirmPrompt: false` 路径，把确认放到 UI 自己的变更集确认页，从根上避免 Core 弹框。

**验证**：IT-07/IT-08 + M-07 手工场景 + 05 篇 §8 的死锁回归测试。

### 2.3 R-03：半装状态

**机理**：TxF 事务的前提是进程/内核能完成回滚；`TerminateProcess`/断电可能让事务进入"无法决定"状态。

**缓解**：

1. 安装前把当前注册表文件**复制备份**到 `%LocalAppData%/CKAN/registry-backup/<timestamp>/`（成本低，救急有效）；
2. 启动时做一致性检查：注册表声明的文件若不存在 → 标记 `Broken` 并在 UI 提供"修复此模组（重装）"；
3. 安装失败的 `possibleConfigOnlyDirs` 与 `OneComplete` 结果都用上，报告要精确到"哪个模组、哪个文件"；
4. `M-08` 手工验收 + IT-09。

### 2.4 R-04：实例锁竞争

**机理**：`RegistryManager` 用锁文件保证单写入者。老 `ckan.exe` 打开同一实例时，新 UI 拿不到锁。

**缓解**：

1. 绝不做"删除锁文件"的自动动作（会破坏数据）；只提供"检测到陈旧锁"的**带警告**的手工修复按钮；
2. 启动时若目标实例被占用，进入只读模式（可浏览、可搜索、不能装）、顶部横幅说明原因与"打开任务管理器"入口；
3. 与用户沟通：新 UI 与老 GUI **不要同时开**同一实例（09 篇 §3）。

### 2.5 R-13：范围蔓延（最容易把项目做死）

**机理**：老 GUI 19,603 行逻辑里散落着几十个小特性（playtime、下载统计、安装历史、托盘、自动更新、代理、稳定性检查、`ckan://`…）。逐个人肉"补齐"会让工期翻倍。

**缓解**：

1. 00 篇 §3 的范围表是**契约**：表外的一律进"M6 及以后"，写进 backlog 但不动手；
2. 每个里程碑结束做一次"范围审计"：新增了什么、推迟了什么；
3. M2 门禁通过后即可对外发布"预览版"，用真实反馈决定 M4 做哪些特性（而不是猜）。
