## 2. 各层要点

### 2.1 纯函数层（Model 迁移 + 过滤排序）

| 测试对象 | 用例要点 |
|---|---|
| `ModSearch`（搬自 `GUI/Model/ModSearch.cs`） | 名称/作者/标签/描述匹配；`is:installed`、`license:` 等前缀；大小写；非法语法不抛异常而返回空 |
| `ModChange`（`GUI/Model/ModChange.cs:50`） | 从 (registry, toInstall, toRemove) 构造出正确动作集；替换同一 identifier 的不同版本 |
| `ModList` 抽出的纯函数 | 更新检测（installed vs latest）、兼容判定、auto-installed 标记 |
| `Filtering.Apply` | 搜索 ∧ 安装状态 ∧ 兼容 ∧ 标签 ∧ 仓库，组合正确；空结果不崩 |
| `Sorting.By(column, direction)` | 稳定排序；空值排末尾；版本号比较用 `ModuleVersion` 而非字符串 |

### 2.2 ViewModel 层（headless）

**前提**：所有服务打桩（`IRepositoryService` 返回手工构造的快照）。

| 断言类别 | 内容 |
|---|---|
| 状态转移 | 搜索文本变化 → 150ms 后 `Rows` 更新且只更新一次 |
| 命令可用性 | `ApplyChanges.CanExecute` 在无变更/有冲突时为 false |
| 线程不变量 | 所有 `PropertyChanged` 来自 `FakeDispatcher` 的"UI 线程" |
| 资源释放 | `Deactivate()` 后事件计数归零（用计数型 FakeService） |
| 错误路径 | 服务抛异常 → `IErrorReporter` 收到一次，`IsBusy` 复位 |

`FakeDispatcher` 的实现要点：

```csharp
public sealed class FakeDispatcher : IDispatcher
{
    private readonly int _uiThreadId = Environment.CurrentManagedThreadId;
    public bool CheckAccess() => Environment.CurrentManagedThreadId == _uiThreadId;
    public void Post(Action a) => _queue.Enqueue(a);
    public T Invoke<T>(Func<T> f) { Assert.That(CheckAccess()); return f(); }
    public void DrainQueue() { while (_queue.TryDequeue(out var a)) a(); }
}
```

> 注：真实使用时，测试在单线程上下文跑，`Post` 的队列由测试显式 `DrainQueue()` —— 这让"是否封送"变成可断言的事实，而不是靠时序碰运气。

### 2.3 集成测试（沙盒 KSP 实例）

`CkanUI.TestSupport.SandboxInstance`：在临时目录构造一个最小 KSP 目录树（`GameData/`、`KSP_x64.exe`、`readme.txt` 等够 `GameInstance` 识别的最小集合），并指向一个**本地假仓库源**（预先打包好的 3–5 个极小模组 zip + 一份 `.repo.json`），因此测试**完全离线**。

| 编号 | 用例 | 关键断言 |
|---|---|---|
| IT-01 | 新建实例 → 打开注册表 → 关闭 | 锁文件创建与释放 |

| IT-03 | 安装带 2 层依赖的模组 | 依赖也被装上，`auto-installed` 标记正确 |

## 3. CI 设计

```yaml
# .github/workflows/ci.yml 要点
strategy:
  matrix:
    os: [windows-latest, ubuntu-latest, macos-latest]
steps:
  - checkout（含 submodules: recursive）
  - setup-dotnet 10.0.x
  - dotnet build -warnaserror
  - dotnet test --filter Category!=RequiresTxF     # 非 Windows 排除 TxF 用例
  - windows: dotnet test --filter Category=RequiresTxF
```

| 门禁 | 要求 |
|---|---|
| 编译 | 0 warning（`TreatWarningsAsErrors`） |
| 单测 | 全绿，核心逻辑覆盖率 ≥60% |
| 集成测试 | Windows 全绿；其他平台只读子集绿 |
| 架构测试 | `ViewModels` 项目不得引用 Avalonia（用 `Microsoft.CodeAnalysis` 或 csproj 结构断言） |
| 时长 | 全套 ≤ 12 分钟（超过说明集成测试太重，拆分 `[Category("Slow")]`） |

## 9. 存档工作台与 SFS 格式化（E1 验收，v1.4）

> 依据 [13 篇](13-savegame-sfs.md) §11。这一域的验收与 mod 管理**完全不同**：它不是"功能有没有"，而是"**文件有没有被动坏**"，因此核心是三条字节级不变量。

### 9.1 三条不变量（每个 PR 都跑，进 CI）

| ID | 不变量 | 断言方式 | 覆盖 |
|---|---|---|---|
| INV-1 | **往返一致**：`Serialize(Parse(bytes)) == bytes` | 对夹具集逐个比较字节（SHA-256 相等） | 10 个真实 `.sfs`（4.3–5.3MB，含中文名与 `默认` 目录） |
| INV-2 | **幂等**：`Format(Format(x)) == Format(x)` | 两次格式化后 SHA-256 相等 | 同上 + 人工构造的畸形样本 |
| INV-3 | **值不变量**：格式化前后 `{(path,key) → value}` 多重集完全相等 | 解析两侧建字典比较；另外单独断言 `GAME.UT`、`GAME.Seed`、`*_modVersions` 三个超长/高精度值**字面相同** | 夹具集 + 属性测试（随机生成节点树） |

> 夹具来源：`<KSP>/saves/默认/` 的 `persistent.sfs`（4.86MB / 270,706 行）、`quicksave.sfs`（5.11MB）、`快速存档.sfs`（5.33MB）、`Codex_GC_AB_20261023.sfs`（4.84MB）等；**不进仓库**，测试启动时按环境变量 `CKAN_TEST_SAVES` 软链接，缺失则跳过并以 `[Skipped]` 计入报表（不允许静默通过）。

### 9.2 坏文件矩阵（必须逐个"识别 + 定位行号"，且不得崩溃）

| 样本 | 期望 |
|---|---|
| 删掉一个 `}` | V-01 错误，给出首个失衡行；格式化拒绝执行 |
| 末尾截断到一半 | V-01 错误 + `OpaqueLine` 计数 |
| 注入 BOM | V-05 警告，`--fix` 可移除 |
| LF/CRLF 混合 | V-05 警告，格式化按多数派统一 |
| 缩进用 3 空格 | V-06 警告，`--fix` 可修正 |
| 同行 `NODE {` 写法 | 解析成功，格式化后独占一行 |
| 值里含 `{`/`}`/`=`/`\` | 解析成功，值字面不变（L7） |
| 100 层嵌套 | V-07 警告，不栈溢出（用显式栈） |
| 单行 1MB | V-07 警告，不 OOM |

### 9.3 安全网测试（破坏性）

- 写盘中途 `kill -9` 进程（注入了 200ms 写延迟）：原文件哈希不变、`*.pre-edit-*.sfs` 存在且可用。
- 只读目录：`ISaveWriter` 返回明确错误码，UI 显示"目录不可写"，不产生临时文件残留。
- KSP 进程存在（用假的 `KSP_x64.exe` 进程模拟）：UI 警示条出现，写盘按钮禁用。

### 9.4 手工验收（H-7 组，M7 出口）
