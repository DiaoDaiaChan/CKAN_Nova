# 03 UI 规格

> 目标：把现有 WinForms GUI（`GUI/Controls/*` 8,085 行 + `Dialogs/*` 3,571 行 + `Main/*` 3,507 行的界面部分）翻译成 Avalonia 视图清单与交互规格。
> 本文只定义"有什么、长什么样、怎么交互"，不定义实现。

## 1. 信息架构

```
主窗口 (MainWindow)
├── 左侧导航栏 (NavRail)
│   ├── 模组 (Mods)              ← 默认页
│   ├── 变更集 (Changes)          ← 有变更时出现角标
│   ├── 实例 (Instances)
│   ├── 仓库源 (Repositories)
│   └── 设置 (Settings)
├── 顶部工具条 (TopBar)
│   ├── 实例下拉 + 切换
│   ├── 搜索框（全局，Ctrl+F）
│   ├── 刷新仓库源按钮 + 最近刷新时间
│   └── 操作状态区（下载/安装中：进度环 + 取消）
└── 内容区 (ContentHost)
    ├── ModsView（主从布局：列表面板 + 详情面板）
    ├── ChangesView
    ├── InstancesView
    ├── RepositoriesView
    └── SettingsView
```

模态/浮层：

| 类型 | 清单 |
|---|---|
| 模态对话框 | 实例新增/编辑、实例克隆、设置子项（安装过滤器编辑器）、modpack 导入预览、冲突解决 |
| 非模态浮层 | 变更集确认、进度详情（可展开的任务队列）、错误详情（技术细节折叠） |
| 系统级 | 崩溃报告、首次启动向导（无实例时） |

### 3.3 行状态视觉

| 状态 | 视觉 |
|---|---|
| 已装且最新 | 正常，左侧绿色竖条 |
| 已装有更新 | 绿色竖条 + 最新版本列加粗 + 行尾 "↑" |

### 3.4 搜索

- 语法支持同 `GUI/Model/ModSearch.cs`（716 行，**可直接复用**）：按名称、作者、标签、描述、`license:`、`is:` 等前缀；
- 交互：输入框 150ms 防抖；命中数实时显示在状态栏；
- 空查询 = 全部；`Ctrl+F` 聚焦，`Esc` 清空。

### 3.5 过滤

| 过滤器 | 选项 | 默认 |
|---|---|---|
| 安装状态 | 全部 / 已装 / 未装 / 有更新 | 全部 |
| 兼容性 | 全部 / 仅兼容当前版本 | 仅兼容 |
| 标签 | 多选（来自 `ModuleTag` 体系） | 全部 |
| 来源仓库 | 多选 | 全部 |
| 自定义（install filters） | 复用 `IConfiguration.InstallFilters`（以源码为准） | 全部 |

过滤器与搜索为**逻辑与**，且与应用级"启用 install filters"开关联动（与老 GUI 语义一致）。

### 3.6 选择与变更集

- 单击行 = 选中（详情面板跟随），不改勾选；
- 点击复选框 = 加入/移出变更集；
- 任何勾选变化 → 后台重算变更集（含隐式依赖）→ 状态栏更新 `+n/-m`；
- 变更集计算结果**不清空用户选择**，只更新"隐式加入"集合；
- 关闭页面前若有未应用变更：不拦，但顶部导航"变更集"出现角标。

## 4. V-02 ChangesView

| 区块 | 内容 |
|---|---|
| 摘要 | "将安装 3 个、升级 1 个、卸载 0 个；预计下载 45.2 MB" |

| 主按钮 | [开始] → 进入执行流 |

### 4.1 执行流状态机

```
Idle → 确认中(Core 或本 UI 询问) → 下载中(可取消) 
  → 安装中(可取消，但取消=回滚) → 完成(汇总：成功 n / 失败 m / 跳过 k)
                                           ├─ 全成功 → 刷新注册表 + Toast
                                           ├─ 部分失败 → 错误详情页（可重试失败项）
                                           └─ 用户取消 → 提示"已回滚，未改动"
```

取消语义（重要）：

| 阶段 | 取消的处理 |
|---|---|
| 下载中 | 立即停，删除临时文件（Core 的 `NetAsyncModulesDownloader` 行为，SP-09 验证） |
| 安装中 | 发出取消 → 等待当前模组完成 → 事务回滚 → 报告"已取消" |
| 安装中（用户强制关闭窗口） | 因为 `CkanTransaction`+强杀可能留半装，见 08 篇 R-03 |

**实现注记（下载重试与续传，UI-35 落地）**：下载中遇到网络类失败不会立刻弹错误，而是最多自动重试 3 次
（400ms → 1200ms 递增退避，`DownloadRetryPolicy`），进度文案变成「正在重试 …（第 n/3 次）：原因」；
重试复用同一个临时文件，传输层把已有字节数交给 Core 的 `Range` 续传，只补下剩余字节。
三次都失败才把失败交给错误详情页（`DownloadsFailedDialog` 的逐项重试/跳过）。
校验类失败（大小 / SHA256）与用户取消**不重试**——同一份坏数据再拉一遍只会再坏一次。

## 9. 键盘与可达性

**页面级**（由页面自己处理，外壳不抢）：

| 快捷键 | 动作 |
|---|---|
| `Ctrl+F` | 聚焦搜索 |
| `Ctrl+R` | 刷新仓库源 |
| `Ctrl+Enter` | 应用变更 |
| `Space` | 切换当前行勾选 |
| `↑/↓` | 移动选中行（不动勾选） |
| `F5` | 重新扫描实例/注册表 |
| `Esc` | 关闭浮层 / 清空搜索 |

**外壳级**（全应用生效，映射表见 `src/CkanUI.App/Input/ShellShortcutMap.cs`，键位只在这一处定义）：

| 快捷键 | 动作 |
|---|---|
| `Ctrl+Tab` / `Ctrl+PageDown` | 下一个页签（当前分节内） |
| `Ctrl+Shift+Tab` / `Ctrl+PageUp` | 上一个页签 |
| `Ctrl+Alt+↓` / `Ctrl+Alt+↑` | 下一个 / 上一个侧栏入口 |
| `Ctrl+1`…`Ctrl+9` | 直达侧栏第 N 项（也认小键盘数字） |
| `Ctrl+,` | 打开设置 |
| `Ctrl+K` | 命令面板 |
| `Ctrl+/` | 快捷键目录 |
| `Ctrl+Shift+A` | AI 助手 |
| `Ctrl+B` | 折叠 / 展开侧栏 |
| `Alt+←` / `Alt+→` | 后退 / 前进 |
| `F1` / `F12` | 功能指引 / 性能探针 |

页签与侧栏的循环带环绕（首尾相接），且只在**真的有多个页签**时才响应 `Ctrl+Tab`——单页分节按下去不该把用户导航走。
命令面板里的「下一个页签 / 聚焦搜索 / 打开设置」等动作与快捷键走同一条 `ApplyShellShortcut` 通路，改键位不会出现「点了没反应、按了才有用」的两套语义。

**手柄**（XInput；`src/CkanUI.Platform/Input/XInputGamepadSource.cs` + `src/CkanUI.Services/Input/GamepadNavigator.cs`，30 Hz 轮询）：

| 输入 | 动作 |
|---|---|
| 方向键 / 左摇杆 | 移动界面焦点（死区 0.5；按住连发：首延迟 350 ms，之后每 120 ms） |
| `A` | 确认 / 按下当前控件 |
| `B` | 返回 / 关闭浮层（顺序与 `Esc` 一致） |
| `X` / `Start` | 命令面板 |
| `Y` | 快捷键目录 |
| `LB` / `RB` | 上一个 / 下一个页签 |
| `LT` / `RT` | 整页上 / 下滚动（只认按下沿，按住不连翻） |
| `Back` | 折叠 / 展开侧栏 |

手柄动作全部落到键盘已有的语义上（焦点迁移走 `FocusManager.TryMoveFocus`，确认合成一次 `Enter`），不为手柄单开一条交互路径；
断开连接时状态机清空按住态，避免重连后凭空触发一次确认。没有手柄时宿主安静地不启动轮询，不影响键盘路径。

可达性要求（M5 门禁的一部分）：所有交互可达且 Tab 顺序合理；不依赖颜色单一通道传达状态（配合图标/文本）；最小对比度 4.5:1；支持系统缩放 100%–200%。
键盘与手柄的焦点一律有可见焦点环（`src/CkanUI.App/Resources/FluentStyles.axaml` 的 `:focus-visible` 段，覆盖按钮、文本框、下拉框、列表项、数据行、开关、单选/复选、滑块与单元格）。

## 10. 空状态与错误态（每页必须有）

| 场景 | 显示 |
|---|---|
| 无实例 | 引导卡片："未找到 KSP 实例，[自动查找] [手动添加]" |

| 网络失败 | 非模态条 + 重试按钮 + 显示离线可用内容 |

## 11. 视觉与本地化规范

| 项 | 规范 |
|---|---|
| 主题 | 起步交付浅色 + 深色；颜色全部走资源字典 |
| 字体 | 系统默认 UI 字体；中文回退显式声明 |
| 间距 | 4 的倍数（4/8/12/16/24） |
| 图标 | 矢量（`Avalonia.Svg` 或内嵌 path），不用位图 |

| 复数与格式化 | 用 `string.Format` + 资源；数字/体积格式化集中一个 `Formatters` 类 |
| Core 文案 | Core 抛上来的消息是英文（`Core/Properties/Resources` 可能已本地化，随语言自动），UI 不二次翻译 |

## 12. 附：材质与动效规范（v1.1 回填，依据 [11 篇](11-tech-stack-decision.md) §4/§6）

**材质降级链**（启动探测一次，结果写入 `ckan-ui.json`）：`Mica`（Win11 build ≥22000）→ `AcrylicBlur`（Win10，需 `win10-x64` RID）→ 纯色 `LayerFillColorDefault`。任一档失败静默降级 + 一条 Warn 日志，**不得崩溃、不得透明穿透**。

**动效 token**（全部走资源字典，视图里不写死时长）：

| Token | 值 | 用在哪 |
|---|---|---|
| `Motion.Fast` | 90ms | 悬停、勾选、行高亮 |
| `Motion.Base` | 150ms | 展开/折叠、页签、过滤 chip |
| `Motion.Page` | 200ms | 页面切换（`CrossFade` 或 `PageSlide` 20px） |
| `Easing.Standard` | `CubicEaseOut` | 全部进入动画 |
| `Easing.Exit` | `CubicEaseIn` | 全部退出动画 |

**禁止**：骨架屏迟于 600ms 才出现、列表行内阴影/模糊、无明确语义的循环动画。

## 14. 存档工作台（E1 新增能力，v1.4）

> 与 [13 篇](13-savegame-sfs.md) 配套。存档能力**不属于**原版 GUI 的功能面（原版没有任何 `.sfs` 代码），因此本节不是"对齐"，而是**新增能力域**；它与 mod 管理正交，放在导航栏最后一个分组，独立里程碑 M7 交付。

### 14.1 信息架构

```
NavRail
 └─ 存档（分组）
     ├─ 存档列表   ← 一个 GameDir 下所有 saves/*
     ├─ 存档详情   ← 选中后进入，三视图页签
     │    ├─ 树视图（默认）
     │    ├─ 原始文本
     │    └─ 差异
     └─ 快照与备份  ← 本程序生成的 *.pre-edit-*.sfs + KSP 自带 Backup/（只读展示）
提示区（页顶常驻）
 ├─ KSP 正在运行警示条（写盘禁止，黄色）
 ├─ 存档目录不可写提示（红色）
 └─ .loadmeta 与 .sfs 不一致提示（可一键修复）
```

### 14.2 存档列表页

| 元素 | 规格 |
|---|---|
| 列 | 槽位名 / 标题（`GAME.Title`）/ 模式（`SANDBOX`|`CAREER`|`SCIENCE`）/ KSP 版本 / UT（按 `RSSTimeFormatter` 式显示）/ 飞船数 / 资金 / 修改时间 / 体积 / 快照数 |
| 行操作 | 打开、格式化…（进预览）、制作快照、在资源管理器中显示、删除（二次确认 + 先快照）、复制槽位 |
| 排序 | 默认修改时间倒序；可切标题/飞船数/体积 |
| 空态 | "这个实例还没有存档" + 打开 `saves/` 目录按钮 |
| 性能 | 50 个存档首屏 ≤300ms（只读 `.loadmeta`，不加载 `.sfs` 全文） |

### 14.3 存档详情页（三视图）

| 页签 | 内容 | 交互要点 |
|---|---|---|
| 树视图 | 按 `GAME` 直接子节点分栏：`FLIGHTSTATE`（飞船→部件→模块）、`SCENARIO`（31 个，按子键 `name`）、`ROSTER`（乘员）、`MESSAGESYSTEM`、`PARAMETERS`、其余 | 虚拟化树 + 懒展开；就地改值（数字/布尔/字符串三套编辑器）；新增/删除键；复制子树；"跳到原始行"；搜索路径 |
| 原始文本 | 全文 + 行号 + 语法高亮（节点名/键/值/花括号/注释四种着色）；默认只读，显式切换"可编辑"（切换时警告） | 5MB 文件首屏 ≤1.5s；分块渲染；Ctrl+F；"在树中定位" |
| 差异 | 编辑前后（草稿 vs 磁盘）/ 存档 A vs 存档 B / 存档 vs 快照 | 节点级折叠、只看变化、逐项采用 |

### 14.4 格式化交互（不做静默格式化）

1. `Ctrl+Shift+F` 或菜单「格式化为规范形式」→ 弹出**预览**：左侧原文、右侧格式化后、底部统计（将改动 N 行缩进 / M 处分隔符 / K 处行尾）。
2. 预览里"仅显示结构差异"勾选（忽略纯缩进变化）。
3. 用户确认 → 自动快照 → 原子写 → 刷新视图并提示 "已快照为 `xxx.pre-edit-20261026-231500.sfs`"。
4. 保存（`Ctrl+S`）**永不自动格式化**；未格式化文件原样写回（保字模式）。

### 14.5 与 mod 管理的关系

- 存档页**只读**实例的 mod 信息：显示"本存档可能依赖 N 个模组（来自 `.loadmeta.kspVersion` 与实例注册表比对，仅提示不阻断）"。
- 不做"存档依赖校验器"（超范围，见 [13 篇](13-savegame-sfs.md) §1.2）。

### 15.3 自动染色的视觉规范（与 §12 材质/动效规范同源）

| 级别 | 字形前缀 | 文字色 token | 说明 |
|---|---|---|---|
| Trace/Debug | `·` | `Log.Trace` | 默认过滤掉 |
| Info | （无） | `Log.Info` | 正文色 |
| User（IUser 消息） | `»` | `Log.User` | 蓝，区别于系统日志 |
| Warn | `!` | `Log.Warn` | 黄 |
| Error | `×` | `Log.Error` | 红 |
| Fatal | `×` + 底色 | `Log.Fatal` | 红底反白 |

- **族标签**（`Net`/`Download`/`Solve`/`Install`/`Fs`/`Reg`/`Save`/`Sec`/`Ui`）以 12px 灰底胶囊显示在级别之后，颜色同名 token 的 20% 透明度。

- 搜索命中与 AI 证据行统一用 `Log.Highlight` 底色，AI 证据行额外加左侧 2px 竖线。

### 15.4 发送预览对话框（AI 的唯一出口）

- 左：**将要发送的完整文本**（可编辑、可裁剪、可删除段落）。
- 右：统计卡（字符数 / 预估 token / 估算费用 / 包含文件清单）+ 固定警示"这是要发到第三方服务的日志"。
- 底部：主按钮 **"发送"**，次按钮"取消"；`Enter` 默认指向**取消**（防误触）；首次使用还需勾选"我了解日志会被发送到第三方"。

### 15.5 AI 结果面板

- 顶部 banner（固定）："AI 可能出错，请以日志证据为准"。
- 每条假设一张卡：`cause` + 置信度条 + **证据行 chip（`#Seq`，点击跳到主列表并高亮）** + `fix`（用户可执行的下一步）。
- 置信度 <0.5 的卡片默认折叠。
- 底部："重新分析"、"复制结论"、**"这条是错的"**（仅本地记录，不上传）。

## §17 E4 本地化对 UI 的约束（v1.8 新增，依据 [16 篇](16-i18n.md)）

### 17.1 布局硬规则（德语 +45% 都不许破）

1. 按钮/标签**禁止固定宽度**：`Width` 用 `Auto` + `MinWidth`；工具栏优先收进溢出菜单（`WrapPanel`）；
2. 表格列宽 `Auto`，首屏按内容测量；宽内容列给 `MinWidth` 而非固定 `Width`；
3. 长文本 `TextTrimming="CharacterEllipsis"` + `ToolTip` 全文；
4. 表单标签列宽度**按当前语言实测一次**（切语言时重算，不写死）；
5. 任何"按英文字符数估算"的注释视为 bug。

### 17.2 字体与字号

- 全局 `Typography.axaml` 定义后备链：`Inter, Microsoft YaHei UI, Microsoft YaHei, SimSun, Yu Gothic UI, Meiryo, Malgun Gothic, Segoe UI`。
- DPI 与字号缩放沿用 `02`/`03` 既有规则；CJK 下字重 400/600 两级即可（避免 SimSun 无 600 时合成假粗体）。

### 17.3 语言选择控件

- 设置页「语言」下拉：每项 `简体中文 · Chinese (Simplified) · 99%`（覆盖率来自 `ILocalizer`）。
- 切换后**立即生效**；弹一条系统消息说明"历史日志保持原文"。
- 语言选择**不进** `ckan-ui.json`（唯一真相是 Core 的 `config.json:Langage`，保证与 `ckan.exe` 互通）。

### 17.4 未翻译内容的呈现

- Core 消息（L3）若当前语言缺译，会以英文出现——**不额外提示、不机器翻译**；语言下拉的覆盖率百分比已提前告知。
- Mod 元数据（`abstract`/`description`）由 [17 篇](17-mod-metadata-i18n.md) 的译文包提供；无译文时英文兜底（v1.1 修订：原文"始终英文"作废，见 17 篇 §14）。

## §18 E5 Mod 摘要与元数据展示（v1.2 新增）

**18.1 ModInfo 摘要块**

- 译者优先：有译文显示译文，无译文显示英文（不做自动遮罩、不加骨架屏）；
- 徽标行（小号、次要色）：`人工译文`（绿）/ `机器翻译`（灰）/ `原文已更新`（黄）；
- 原文展开：`▸ 显示英文原文`（可折叠，默认收起；展开后译文仍在，便于对照）；
- 无译文态：右侧「翻译此 mod」按钮（仅在允许机翻档可见）。

**18.2 列表**

- `Description` 列显示译文；「视图」菜单提供 `显示原文摘要` 开关（逐列不单独切换）；
- 命中译文时的搜索标记：行尾 4px 竖条 + tooltip「命中的是译文」。

**18.3 布局硬规则（继承 §17 的膨胀预算）**

- 中文通常比英文短，但**日语/俄语可能更长**：摘要块高度不固定，允许 1–4 行自动换行，超过 4 行折叠 + 「展开」；
- 徽标行不得挤压标题行；`原文已更新` 与 `机器翻译` 同时出现时只显示黄标（黄 > 灰 > 绿 的视觉优先级）。

## §19 E6 启动游戏后的 UI 形态（v1.3 新增）

**19.1 三个状态**

| 状态 | 界面表现 |
|---|---|
| 启动中（T0–T2） | 按钮变"正在启动…"、进度条不确定态；**不**做任何释放 |
| 让路中（T3–T5） | 窗口最小化/退托盘；托盘图标带小圆点表示"正在为游戏让出资源" |
| 精简模式（游戏运行中） | 若用户唤回窗口：标题栏加 `精简模式` 徽标；列表只读、安装/卸载禁用并给理由；搜索只走标识符前缀 |

**19.2 完成提示**

T5 结束后一次非模态提示（托盘气泡或窗口内横幅）：

> 已为游戏让出 **238 MB**（托管堆 186 MB / 工作集 52 MB）。游戏退出后会自动恢复。

- 数字必须来自实际读数（§10 的 metrics），**不许写死**；
- 一键"立即恢复"按钮；"不再提示"选项。

**19.3 恢复期**

- 骨架行 + 进度条（`正在恢复数据 12.4 MB / 37.9 MB`）；
- **禁止空白列表**；恢复完成后不跳动（保持滚动位置）。

## §21 E8 外观设置页与个性化 token 表（v1.5 新增）

依据 [20 篇](20-appearance-personalization.md) §13。

**页面**：`V-05 设置 → 外观`，左侧 6 组（主题 / 颜色 / 材质 / 形状 / 版面 / 背景），右侧常驻**实时预览迷你窗**（三行一卡，用两个 `ThemeVariantScope` 并排显示浅/深）。

| 组 | 控件 | 说明 |
| --- | --- | --- |
| 主题 | 分段控件：跟随系统 / 浅色 / 深色；下面主题包卡片（内置 3 + 用户导入，含 200×120 预览图） | 主题包卡片右上角标"深/浅"基线 |
| 颜色 | 强调色：跟随系统 / 12 预设色块 / 自定义 hex 输入；旁边一枚对比度徽标（AA / AAA / 不合规） | 不合规时主按钮禁用 + 给 3 个建议色 |
| 材质 | 窗口材质：自动 / 磨砂 / 纯色；只读一行"当前实际：Mica / Acrylic / 纯色（原因）" | 纯色时隐藏 tint 相关项 |
| 形状 | 圆角三档（0/6/12 的示意块）；"实验性：Win10 窗口圆角"开关 + 风险提示 | 开关仅在 Win10 显示 |
| 版面 | 密度三档 / 字号五档 / 动效三档（含"跟随系统"复选） | 改完立即生效，无需确认 |
| 背景 | 来源（纯色 / 渐变 / 图片 / 游戏截图）+ 填充 / 暗化 / 模糊 / 不透明度 + "仅本实例" | 暗化默认值随深浅色不同 |

页脚：`恢复本组默认` / `恢复全部默认` / `导出外观…` / `导入外观…`。

**布局硬规则**（接 §11/§17）：外观控件本身也必须用 token（否则"改主题把设置页改花"）；所有示意块用 `ThemeVariantScope` 渲染成用户当前选择的样子，不做抽象色块。
