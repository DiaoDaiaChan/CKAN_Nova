## §1 目标与非目标

### 1.1 目标

| ID | 目标 | 验收指向 |
|---|---|---|
| I-01 | **不改一行官方 resx**，就能用上官方 13 种语言的既有翻译 | §5 快照复用 |
| I-02 | 新版 UI 自己的新增文案有**独立目录**，键名语义化、可交给 Crowdin | §5 键规范 |
| I-03 | 解析顺序固定：新表 → 官方快照 → Core 运行时 → 英文 | §3 三层 |
| I-04 | 语言**切换即时生效**（不重启应用；Core 已产出的消息不回改） | §6 |
| I-05 | 与 `ckan.exe` 共享同一个 `Config.Language`，双向可读 | §6.3 |
| I-06 | 缺译**可见**：语言下拉显示覆盖率，构建期产出缺译清单 | §4.5 |
| I-07 | CJK／德语／俄语下布局不破 | §7 |
| I-08 | 数字、日期、大小单位按当前区域格式化，但**存盘一律 Invariant** | §8 |

### 1.2 非目标

- ❌ 不翻译 Mod 元数据（`abstract`／`description` 来自 CKAN-meta，仅英文；这是数据不是 UI）。
- ❌ 不翻译 `.sfs`／`.cfg` 文件内容（E1/E3 的原始文本视图永远原样）。
- ❌ 不动 Crowdin 上已有的官方语言包内容（有错另提 PR）。
- ❌ 不实现 RTL 语言（官方无 `ar`／`he`；Avalonia 的 `FlowDirection` 支持保留但不验收）。
- ❌ 不引入机器翻译流水线（术语一致性优先于覆盖率）。

## §2 现状取证（官方 GUI 的 i18n 是怎么工作的）

### 2.1 资源分布（仓库实测）

| 资源集 | 文件 | 字符串数（英文基准） | 位置 |
|---|---|---|---|
| Designer 文案 | 36 个 resx | **420** | `GUI/Main/*.resx`、`GUI/Controls/**/*.resx`、`GUI/Dialogs/*.resx` |
| GUI 文案目录 | 1 个 | **314** | `GUI/Properties/Resources.resx` |
| Core 文案目录 | 1 个 | **209** | `Core/Properties/Resources.resx` |
| **合计** | | **943** | |
| 各语言翻译 | 13 个目录 ×36 文件 | — | `GUI/Localization/<locale>/*.<locale>.resx`、`GUI/Properties/Resources.<locale>.resx`、`Core/Properties/Resources.<locale>.resx` |

### 2.2 加载机制

- 清单显示本地化经 **`SingleAssemblyComponentResourceManager`**（`GUI/SingleAssemblyComponentResourceManager.cs:13`，内部类，`internal`）。
- 它 `override InternalGetResourceSet(CultureInfo, bool, bool)`：先用 `MainAssembly.GetManifestResourceStream(contextTypeInfo, GetResourceFileName(culture))` 从**同一程序集**里取流（`:36`），取不到才回退 `base.InternalGetResourceSet(...)`（`:44`）。
- 这正是"翻译文件被打进 exe 本体、不走卫星程序集"的原因——由 `GUI/CKAN-GUI.csproj:89-94` 的 `EmbeddedResource Update="Localization\**\*.resx"` 配合 `WithCulture` 决定清单名。
- **结论**：官方翻译与控件类型强耦合（`typeof(ManageMods)` 决定清单名）。新 UI 里没有这些 WinForms 类型，因此**不能直接 `new SingleAssemblyComponentResourceManager(typeof(...))`**，只能按清单名直接读资源流或复制 resx。

### 2.3 文化与启动时机

`GUI/Main/Main.cs:104-111`：

```csharp
if (string.IsNullOrEmpty(mainConfig.Language))
{
    string runtimeLanguage = Thread.CurrentThread.CurrentUICulture.IetfLanguageTag;
    mainConfig.Language = runtimeLanguage;
}
else
{
    CultureInfo.DefaultThreadCurrentUICulture = Thread.CurrentThread.CurrentUICulture = new CultureInfo(mainConfig.Language);
}
```

- 只设 **`CurrentUICulture`**（不设 `CurrentCulture`）→ 数字／日期仍按系统区域。
- 时机在 `InitializeComponent()` **之前**，所以 Designer 里 `resources.GetString(...)` 取到的是目标语言。
- 反过来也意味着：**运行中改 `Config.Language` 对已建控件无效** → 必须重启（见 §2.5）。

### 2.4 配置与校验

- `Config.Language` 是 `config.json` 的一个键（`Core/Configuration/JsonConfiguration.cs:149` 用 `Utilities.AvailableLanguages.Contains(value)` 校验）。
- `Core/Utilities.cs:18` 的 `AvailableLanguages` 有 **13 项**：`en-GB, en-US, de-DE, zh-CN, fr-FR, pt-BR, ru-RU, ja-JP, ko-KR, pl-PL, tr-TR, it-IT, nl-NL`。
- 界面：`GUI/Dialogs/SettingsDialog.cs:762-768` 用 `Utilities.AvailableLanguages` 填下拉、`FindStringExact(coreConfig.Language)` 选中；`:795-797` 选择变更时**只写配置**。

### 2.5 切换语言的真实行为

`SettingsDialog` 写配置后不重建界面、不提示重启（`:795-797` 无任何 UI 反馈），语言在**下次启动**才生效。老 GUI 的"改了没反应"体验即来源于此。

### 2.6 两处上游不一致（我们必须在自己的实现里绕开）

1. **`es-ES` 有翻译但无法选择**：`GUI/Localization/es-ES/` 有 36 个文件（designer 覆盖 **387/420**、GUI 目录 **34/314**、Core **60/209**），但 `AvailableLanguages` 里**没有 `es-ES`**。
2. **`en-GB` 可选项没有对应资源**：`AvailableLanguages` 含 `en-GB`，`GUI/Localization/` 下**无 `en-GB` 目录** → 选中后落回英文中性资源（行为可接受，但用户会以为坏了）。

## §3 决策 D11：先复用官方，再补新增

| 层 | 内容 | 来源 | 查询时机 |
|---|---|---|---|
| **L1 新表** | 新版 UI 独有的文案（NavRail、日志页、存档页、配置页、AI 面板…） | `CkanUI.App/Properties/Resources.resx` + `.resx` 各语言 | 最先 |
| **L2 官方快照** | 官方 943 条（键名与英文原文原样保留） | 构建期从 `GUI/**/*.resx` + `GUI/Properties/Resources.resx` **复制**进 `CkanUI.Localization.Legacy` | L1 未命中 |
| **L3 Core 运行时** | Core 的 209 条错误消息 | 直接调用 `CKAN.Properties.Resources.ResourceManager`（引用 Core 即可，**不复制**） | L2 未命中 |
| **L4 英文基准** | 中性资源（= 官方英文原文） | L1/L2 的 neutral resx | 最终 |

**为什么 L2 复制而不是引用**：`GUI` 是 `WinExe` + WinForms，新项目不能引用它；而 `SingleAssemblyComponentResourceManager` 又被 `GUI` 类型名绑死（§2.2）。复制 resx 是**唯一不改官方文件、又能拿到 927 条已译文案**的做法，且成本是构建脚本 10h（I18N-05）。

**为什么 L3 不复制**：Core 是普通类库，`Resources.<locale>.resx` 会编成卫星程序集、`ResourceManager.GetString(key, culture)` 直接可用；复制反而会在官方修错别字时僵死。

**推论（重要）**：新版 UI 复用的不是"官方控件的字符串"，而是**官方 943 条文案 + 已译 927 条**这个事实。新老界面控件不同，因此需要一层**显式映射**（§5.2），而不是靠键名撞运气。

## §4 架构

```
CkanUI.Localization          （类库，纯 .NET，无 Avalonia 依赖）
├── ILocalizer               Get(key) / Format(key, args) / CurrentCulture / LanguageChanged
├── Localizer                L1→L2→L3→L4 解析、缓存 ResourceManager、缺译计数
├── LegacyCatalog            L2 官方快照（EmbeddedResource，键名 = 官方键名）
├── CoreCatalog              L3 反射 Core.Properties.Resources.ResourceManager
└── LocaleInfo               locale / 显示名（本地名 + 英文名）/ 覆盖率

CkanUI.App.Localization      （Avalonia 层）
├── LocExtensions            {loc:T Key} / {loc:T Key, Format={0}}
├── LocalizerExtensions      AddLocalization(IServiceCollection)
└── LanguageSwitcher         写 Config.Language + 通知 LanguageChanged

tools/LegacyResxSync         构建期工具（net10 console）
└── 从 ../CKAN/GUI 复制 resx → CkanUI.Localization/Legacy/，并生成 legacy-index.json
```

### 4.1 `ILocalizer` 契约

```csharp
public interface ILocalizer
{
    CultureInfo CurrentCulture { get; }
    event EventHandler<CultureInfo>? LanguageChanged;

    string  Get(string key);                            // 缺键返回 key 本身并计数
    string  Format(string key, params object?[] args);  // string.Format(Get(key), args)
    bool    TryGet(string key, out string value);       // 用于"是否有官方译文"探测
}
```

### 4.2 解析顺序（伪代码）

```csharp
string Resolve(string key, CultureInfo c)
{
    // L1 新表
    if (TryRes(newStrings, key, c, out var s)) return s;     // 逐级 culture → parent → neutral
    // L2 官方快照
    if (TryRes(legacyStrings, key, c, out s)) return s;
    // L3 Core（仅当 key 带 "Core." 前缀，避免与 GUI 键冲突）
    if (key.StartsWith("Core.") && TryCore(key[5..], c, out s)) return s;
    // L4 缺译：计数 + 返回 key
    MissingKey(key, c);
    return key;
}
```

`TryRes` 的 culture 链是 `zh-CN → zh → neutral`，与 .NET `ResourceManager` 一致；**不做跨语言回退**（不拿 zh 译文去填 ja 的空位），缺就缺，覆盖率会显示。

### 4.3 与 Avalonia 的结合

- 标记扩展 `{loc:T Ui_NavRail_ManageMods}` 返回一个 `IObservable<string>`：
  ```csharp
  public override object ProvideValue(IServiceProvider sp)
      => new LanguageObservable(localizer, key).Select(() => localizer.Get(key)).ToBinding();
  ```
  内部把 `localizer.LanguageChanged` 包成 `IObservable<CultureInfo>`，语言一变，**所有绑定自动失效重算** → 即时切换（I-04）。
- **禁止**在 `*.axaml.cs` 里 `localizer.Get(...)` 后赋给 `Text`（一次性求值，切换后不更新）。
- 一次性文案（`ContentDialog` 标题、`Toast`）允许代码取值，但必须在 `LanguageChanged` 时重建。

### 4.4 热切换的边界（必须写进用户可见文案）

| 对象 | 切换后 |
|---|---|
| 新版 UI 所有文案（绑定） | ✅ 立即变 |
| Core 之后产生的消息（`IUser.RaiseMessage`、异常文本） | ✅ 立即变（`CurrentUICulture` 已改） |
| **已经显示在日志／状态栏里的历史消息** | ❌ 不回改（消息字符串生成即定型） |
| 存档／配置原始文本视图 | ❌ 不翻译（非目标） |

UI 在切换后给一条系统消息："界面已切换为简体中文；已显示的历史日志保持原文。"

### 4.5 缺译可见

- 语言下拉每项右侧显示 `简体中文 99%`（按 L1+L2 的已译键数 / 总键数计算，L3 单独统计）。
- 构建期任务 `dotnet run --project tools/LegacyResxSync -- --report` 产出：
  - `doc/uir/i18n/coverage-official.csv`（已有）
  - `CkanUI.Localization/missing.<locale>.txt`（每个 locale 缺哪些键，供 Crowdin 上传时对照）

## §5 键规范与官方映射

### 5.1 新键命名（L1）

```
Ui.<Area>_<Element>[_<Qualifier>]
例：Ui_NavRail_ManageMods
    Ui_Log_Filter_Error
    Ui_Saves_FormatConfirm_Title
    Ui_Msg_Install_Completed          // Format 占位符用 {0}
```

- 只用 ASCII 字母、数字、下划线；**不出现**控件类名（`ToolStripMenuItem` 这种）。
- 区域词表固定：`NavRail / ManageMods / ModInfo / Changeset / Settings / Instances / Repos / Log / Saves / ModConfig / Tray / Common`。
- 复数／数量文案**不依赖复数规则**（§8.3）。

### 5.2 官方键映射（L2 的唯一入口）

`CkanUI.Localization/legacy-map.json`：

```json
{
  "Ui_NavRail_ManageMods":      "ManageModsTabPage.Text",
  "Ui_ModInfo_Tab_Contents":    "ContentsTabPage.Text",
  "Ui_Settings_Repositories":   "RepositoryGroupBox.Text",
  "Ui_Msg_Changeset_Applied":   "Core.ChangesetApplied"
}
```

规则：

1. **一条新键最多映射一个官方键**；映射即"我们认可官方该条译文的语义"。
2. 有映射就不必在 L1 写英文——省 927 条翻译的维护量。
3. 语义已漂移的（老 GUI 叫"Apply changes"，新 UI 叫"应用变更"含义略有不同）**不映射**，走 L1 自写。
4. 映射表由 `tools/LegacyResxSync --verify` 校验：键必须存在于官方 resx，否则构建失败（防打字错误）。
5. 覆盖率报告同时给出"直接复用 N 条 / 自写 M 条"，让翻译贡献者知道要翻多少。

### 5.3 术语一致性（实测，不凭感觉）

复用官方译文（L2）本身就把术语对齐了。对 L1 新增文案，以官方译文**实测用词**为准（`doc/uir/i18n/glossary-zh.tsv` 由脚本从 943 条官方条目抽取，可复查）：

| en | 官方 zh 实际用词 | 官方例句 | 出现次数 |
|---|---|---|---|
| Repository | **仓库** | `Repository:` → `仓库：` | 7 |
| Instance | **实例**（"游戏实例"） | `Please enter a name for the new instance.` → `请输入新游戏实例名称.` | 41 |
| Changeset | **更改列表** | `Changeset` → `更改列表` | 3 |
| Unmanaged | **未被管理的文件** | `Unmanaged Files` → `未被管理的文件` | 1 |
| Cached / Uncached | **已缓存 / 未缓存** | `Filter (Cached)` → `筛选 (已缓存)` | — |
| Compatible / Incompatible | **兼容的模组 / 不兼容的模组** | `Filter (Compatible)` | — |
| Upgradeable | **可更新** | `Filter (Upgradeable)` → `筛选 (可更新)` | — |
| Label | **标签** | `Label ({0})` → `标签 ({0})` | 22 |
| Stability tolerance | **稳定性偏好** | `Stability tolerance:` → `稳定性偏好：` | — |
| Identifier | **标识符** | `Identifier:` → `标识符:` | — |
| Contents | **目录内容** | `Directory Contents` → `目录内容` | — |
| Recommendations | **推荐** | `Audit &recommendations` → `审计推荐` | — |
| Mod / Module | **官方混用**：`Mod` 63 处、`模组` 59 处、`模块` 9 处 | — | — |

**两条必须写明的限制**：

1. **L2 复用的部分保留官方原词，不因我们的术语表而改变**——官方混用 `Mod`/`模组`，我们只能保证**自己新写的文案**统一（选 `模组`，与 59 处的多数派一致；紧邻 Mod 专名时保留 `Mod`）。
2. **因此"术语完全统一"不是 I-0x 目标**：要想全统一，只能改写官方译文（= 放弃 L2 复用，成本 +927 条翻译），D11 明确不这么做。

**已有可用素材**：`doc/uir/i18n/seed-zh.tsv`（943 行，`scope/key/en/zh` 四列，927 行有中文），可直接作为句式与术语检索表；`doc/uir/i18n/glossary-zh.tsv` 是上表的机读版（含 `evidence_en` 与 `scope`，便于追溯）。

## §6 语言选择与切换

### 6.1 语言列表的真相源

**不复制 `Utilities.AvailableLanguages`**（它有 §2.6 的两处缺陷）。新 UI 的列表 = **官方资源目录的实际并集**：

```
en-US, de-DE, es-ES, fr-FR, it-IT, ja-JP, ko-KR, nl-NL, pl-PL, pt-BR, ru-RU, tr-TR, zh-CN
```

- 加 `en-GB` 作为"英文（英国）"别名项，指向 `en-US` 资源（保留老用户的配置值可读）。
- `es-ES` 正式可选（补上官方缺失的入口）。
- 显示名用**本地名 + 英文名**：`简体中文 (Chinese, Simplified)`，避免在乱码环境里选不出来。

### 6.2 切换流程

```
用户选语言
  → ILocalizer.SetCulture(ci)          // 设 DefaultThreadCurrentUICulture + CurrentCulture? 否，只设 UICulture（§2.3）
  → 写 Config.Language = ci.Name        // 与 ckan.exe 共享
  → SaveConfig()                        // Core 全量重写（见 09 篇 §3.2 的硬约束）
  → LanguageChanged 事件
  → 所有 {loc:T} 绑定重算
  → 系统消息："界面已切换…；历史日志保持原文。"
```

- **只设 `CurrentUICulture`，不设 `CurrentCulture`**：与官方一致（数字/日期跟系统走）。若用户要求"数字也用目标区域"，那是另一个开关（Q3）。
- 切换是**同步 + 廉价**的（只重算绑定），不需要重启；**不需要**重建 `GameInstanceManager`／`RegistryManager`。
- 有未保存改动时（E3 配置页）先提示。

### 6.3 与 `ckan.exe` 的互操作

- 同一个 `config.json`、同一个 `Language` 键、同一套 locale 名 → 交替使用两个前端不会来回改语言。
- 我们的列表比官方多 `es-ES`：若用户在新 UI 选西语，老 GUI 启动时 `Utilities.AvailableLanguages` 不含它 → `JsonConfiguration.cs:149` 校验不过 → **老 GUI 会退回系统语言**。这是**可接受但必须记录**的行为（Q4：是否只对老 GUI 允许的集合做二次限制）。

## §7 字体与布局

### 7.1 CJK 字体回退（真实风险 R-41）

- Avalonia 的默认字体族不含中日韩字形；若未配置系统字体回退，中文会显示**豆腐块**。
- 设计：`FontFamily` 显式后备链，**按平台**给：

```
Inter, Microsoft YaHei UI, Microsoft YaHei, SimSun, Yu Gothic UI, Meiryo, Malgun Gothic, Segoe UI
```

- 由 `Presentation/Themes/Typography.axaml` 统一定义 `ThemeFontFamily`／`ThemeFontFamilyMono`，禁止在视图里硬编码 `FontFamily`。
- 日文用户若系统只有 `Meiryo`／`Yu Gothic`，混合中文 mod 名要能各自回退（Avalonia 的 per-run 回退是否成立 = **SP-27**）。

### 7.2 文案膨胀

| locale | 相对英文长度 |
|---|---|
| de-DE / ru-RU / pl-PL | +25%～+45% |
| fr-FR / es-ES / pt-BR | +15%～+25% |
| zh-CN / ja-JP / ko-KR | −40%～−55% |

硬约束（写进 `03-ui-spec.md` 的 §2 布局规则补充）：

1. 按钮／标签**不得固定宽度**，用 `Auto` + `MinWidth`；工具栏用 `WrapPanel` 或优先收进溢出菜单。
2. 表格列宽用 `Width="Auto"` + 首屏按内容测量，禁止写死像素。
3. 任何 `TextBlock` 允许 `TextTrimming="CharacterEllipsis"` + `ToolTip` 全量文本。
4. 表单行的标签列宽度按**当前语言实测一次**再定（德语截图回归，见 §9）。

### 7.3 伪本地化（pseudo-locale）

`--pseudo` 启动参数把所有 L1/L2 文案变换为 `[!! Ŝéttïñgş !!]` 并加长 30%：

- 目的：一次性暴露**漏翻**（英文原样残留）与**截断**（布局不够宽）。
- 只在 Debug/CI 构建可用；不发布。

## §8 数字、日期、单位与复数

### 8.1 显示 vs 存盘

- **显示**：`CurrentCulture`（系统区域，与官方一致）。
- **存盘**：`InvariantCulture`——`.ckan`／`registry.json`／`.sfs`／`config.json` 已有的解析逻辑（Core 用 `InvariantCulture`）不可被 UI 的语言设置影响。
- 反例禁令：UI 里 **禁止** `double.Parse(text)` 不带 `CultureInfo`（否则德语用户输入 `2,5` 会被当成 25）。统一走 `NumericInput.Parse(text, CurrentCulture)`，非法即红框。

### 8.2 大小单位

`1.2 MB` 还是 `1,2 MB` 取决于区域 → 用 `SizeFormat.Format(long bytes, CultureInfo)` 集中实现，并按 1024 进制给 `KB/MB/GB`（与官方 `Utilities.FormatBytes` 口径一致，需对齐 SP-27 顺带确认）。

### 8.3 复数：**设计上避免**

- 中文／日文／韩文无复数形态；英／俄／波兰有复杂规则。
- 因此新文案**一律写成不带复数的句式**：
  - ✅ `已安装 {0} 个 Mod` / `{0} mod(s) installed` → 改成 `Installed: {0}` → `已安装：{0}`（用"标签：值"结构）
  - ❌ `There {0} is/are …`
- 例外（必须支持数量词的位置）：由 `Ui.Common_Count` 单一模板 + 语言表里给 `{0}` 位置，不做规则引擎。
- 若将来真需要 CLDR 复数：`10-spike-plan.md` 不设 spike，直接评估 `Humanizer` 依赖（Q5，默认不做）。

## §9 Crowdin 工作流

`crowdin.yml` 现有两条源规则（`/GUI/**/*.resx` 排除 `Properties/`、`Localization/`；以及 `/**/Resources.resx`）。新增：

```yaml
  - source: /CkanUI.App/Properties/Resources.resx
    translation: /CkanUI.App/Properties/Resources.%locale%.resx
```

- **L2 官方快照不进 Crowdin**（它们是官方文件的副本，翻译在官方仓库维护）。
- 上传前校验（`tools/LegacyResxSync --verify`）：
  1. 键集合与上次一致或新增（删除键要显式确认）；
  2. `{0}` 占位符数量与顺序在译文中与英文一致；
  3. 无 HTML 标签差异；
  4. 空值视为缺译（Crowdin 会自动跳过）。
- 下载后校验：`dotnet run --project tools/LegacyResxSync -- --audit` 产出 per-locale 缺译清单，进 CI 报告（不阻断构建）。
